# ADR-0004: Parse and generate order files in the browser

- Status: Accepted — **validated by Spike A (2026-07-13)**
- Date: 2026-07-13
- Deciders: Repo owner

> **Spike A result:** `LargeXlsx` runs under the Blazor WASM runtime, including a **trimmed**
> publish (full Emscripten relink); a generated `.xlsx` re-opened cleanly (openpyxl), with Cyrillic
> and numeric cells intact. The client-side path holds. Caveats for Phase 3, not this decision:
> `template.json` loading must move off `File.ReadAllTextAsync` to `HttpClient` + source-gen JSON,
> and the reflection `TableRowProvider`s want trimmer hardening. See
> [../implementation/02-preflight-spikes.md](../implementation/02-preflight-spikes.md).

## Context

The core work — parsing the Polyboard text file and generating the manufacturer Excel /
`.cut_mt` files (`Kroiko.Domain` + `LargeXlsx`) — is pure .NET with no server
dependencies. With a WASM client ([ADR-0002](0002-blazor-server-to-webassembly.md)) it
could run either in the browser or on the API. Running it in the browser avoids a
round-trip, offloads CPU from the backend, and means the browser already holds the
generated bytes (so downloads need no server or blob storage).

## Decision

We will run **parsing and file generation in the browser**. `Kroiko.Domain` is referenced
by the client and must remain **browser-safe** (no server-only APIs). Downloads are
triggered client-side via JS interop on the in-memory bytes; only **email** sends bytes to
the API.

This decision is gated by **Spike A** (validate `LargeXlsx` runs under the WASM runtime
with trimming). See [../implementation/02-preflight-spikes.md](../implementation/02-preflight-spikes.md).

## Consequences

**Positive**
- No server round-trip for generation; backend stays thin.
- Azure Blob storage likely becomes unnecessary (browser already has the bytes).
- Works offline once loaded.

**Negative / risks**
- Depends on `LargeXlsx` being WASM/trimming-compatible (Spike A). If it fails, this ADR
  is superseded by a server-side-generation variant (`POST /api/generate`).
- WASM is single-threaded; very large files could momentarily block the UI.
- `Kroiko.Domain` is constrained to browser-safe APIs forever.

**Follow-ups**
- Move `DetailsExtractorService` and the `Models/*Extensions.cs` domain rules into
  `Kroiko.Domain`; register the keyed builders in the client.

## Alternatives considered
- **Generate on the API** — guaranteed compatibility, but adds a round-trip and backend
  load, and reintroduces blob/download plumbing. Kept as the documented fallback if
  Spike A fails.
