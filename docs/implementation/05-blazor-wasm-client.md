# Phase 3 — Implementation plan: Build the Blazor WASM client (UI only)

> **Status:** Not started
> **ADR:** [ADR-0002](../adr/0002-blazor-server-to-webassembly.md), [ADR-0004](../adr/0004-client-side-file-generation.md) · **Prerequisite:** Phase 2; Spike A ✅
> **Est. effort:** L (auth rewrite is the hardest single item)
> Index: [00-overview.md](00-overview.md) · Context: [../../CONTEXT.md](../../CONTEXT.md)

## Objective
Create `ATAFurniture.Client` (Blazor WASM, **UI only**), move the MudBlazor UI and the
in-browser file generation into it, and rewire it to call the API with a bearer token.

## Scope
- **In:** WASM project, UI move, domain-into-browser, typed HttpClients, JS download, MSAL auth.
- **Out:** DB/secrets (they stay in the Api), hosting the client (Phase 4).
- **If Spike A failed:** use the server-side-generation variant (see bottom).

## Work breakdown

### P3-T1 — Scaffold `ATAFurniture.Client`
- **Files:** new WASM project (net10); add to `.sln`
- **Do:** `dotnet new blazorwasm -o ATAFurniture.Client`. Reference `Kroiko.Domain` +
  `ATAFurniture.Contracts` only. **No EF / DB / secret references.**
- **Verify:** empty client builds and loads.
- **Depends on:** —

### P3-T2 — Move the UI + MudBlazor wiring
- **Files:** move `Layout/`, `Pages/`, `Components/`, `wwwroot` from `ATAFurniture.Server` → client; client `Program.cs`, `wwwroot/index.html`
- **Do:** `AddMudServices()`; MudBlazor CSS/JS + Roboto in `index.html` (no Syncfusion
  license — removed in Phase 1).
- **Verify:** pages render in the WASM client.
- **Depends on:** P3-T1

### P3-T3 — Move generation into the browser
- **Files:** move `DetailsExtractorService` (`ATAFurniture.Server`) → `Kroiko.Domain`;
  move `Models/*Extensions.cs` domain rules → `Kroiko.Domain`; register keyed builders in client `Program.cs`
- **Do:** register the keyed `ITemplateBuilder`/`ITableRowProvider`/`IFileNameProvider`
  (previously in `Startup.cs`) in the client. **Fix-while-here:** parser skips a bad line
  instead of discarding the whole file; **fail fast** when a builder/provider is missing
  (null-deref bug).
- **Spike 0.5 finding — `template.json` loading:** `TemplateBuilderBase.ReadTemplateAsync`
  reads the template with `File.ReadAllTextAsync`, which has no filesystem in WASM. Fetch each
  `template.json` via `HttpClient` (ship them under `wwwroot`) and pass the content in; the
  `JsonSerializer.Deserialize` is trim-unsafe (IL2026) → deserialize via a `JsonSerializerContext`
  (source-gen). See [02-preflight-spikes.md](02-preflight-spikes.md#findings-for-later-phases).
- **Verify:** parse + `FileGeneratorService` produce correct bytes entirely in-browser.
- **Depends on:** P3-T2

### P3-T4 — Typed API clients
- **Files:** client `Program.cs`, new `Services/*ApiClient.cs`
- **Do:** register an `HttpClient` (base = Api) with `BaseAddressAuthorizationMessageHandler`
  so bearer tokens attach automatically; typed clients for user/credits/email endpoints
  returning `ATAFurniture.Contracts` DTOs.
- **Verify:** `GET /api/user` returns credits into the UI.
- **Depends on:** P3-T2, Phase 2

### P3-T5 — Client-side download (JS interop)
- **Files:** `wwwroot/download.js`, `OrderHandlingComponent`
- **Do:** the browser already holds generated bytes → download without a server hop:
  ```js
  export function downloadBytes(name, type, bytes) {
    const url = URL.createObjectURL(new Blob([bytes], { type }));
    const a = document.createElement('a'); a.href = url; a.download = name; a.click();
    URL.revokeObjectURL(url);
  }
  ```
  **Remove** the Azure Blob upload + local-disk write + `_sessionDirs` cleanup.
- **Verify:** download produces the correct file for each company.
- **Depends on:** P3-T3

### P3-T6 — Rewire order actions to the API
- **Files:** `OrderHandlingComponent`, `UserCreditsComponent`, rewrite `UserContextService` as a client
- **Do:** email → `POST /api/email/send` (bytes + contact); credit consume → `POST
  /api/credits/consume` **awaited** (fix fire-and-forget; mark consumed only on success);
  `UserContextService` reads claims locally but fetches credits via `GET /api/user`.
- **Verify:** email sends via Api; a credit is consumed exactly once; UI reflects balance.
- **Depends on:** P3-T4, P3-T5

### P3-T7 — Authentication (MSAL in the browser)
- **Files:** client `Program.cs`, `App.razor`, `wwwroot/appsettings.json` (non-secret)
- **Do:**
  ```csharp
  builder.Services.AddMsalAuthentication(o => {
      builder.Configuration.Bind("AzureAdB2C", o.ProviderOptions.Authentication);
      o.ProviderOptions.DefaultAccessTokenScopes.Add("api://<api-app-id>/access_as_user");
  });
  ```
  wrap in `CascadingAuthenticationState` + `AuthorizeRouteView`; port `[Authorize]` on the
  converter page. **Azure AD B2C portal:** add a **SPA redirect URI**, expose the API
  scope, grant the client that scope (from Spike C).
- **Verify:** sign in → token acquired → reaches the Api (200); anonymous → login redirect.
- **Depends on:** P3-T4

### P3-T8 — Client concerns (logging, config, trimming)
- **Do:** browser logging (Sentry WASM/Blazor or console); client config holds only public
  values (Api base URL, B2C client id/authority/scope); enable trimming; measure payload.
- **Spike 0.5 finding — trim-fragile reflection:** `MegaTrading`/`Suliver` `TableRowProvider`
  read columns via `Type.GetProperty` (IL2070). They survived the trimmed spike (properties were
  otherwise referenced), but harden them so a future change can’t silently blank cells —
  source-gen the mapping, add `[DynamicallyAccessedMembers(PublicProperties)]` to the detail type,
  or add a trimmer-roots descriptor. LargeXlsx/`ExcelFileGenerator` itself is trim-clean.
- **Verify:** no secret in the shipped bundle; acceptable first-load size; MegaTrading/Suliver
  `.xlsx` still fully populated from the **trimmed** publish (not just Debug).
- **Depends on:** P3-T2

## Sequencing
T1 → T2 → T3 → (T4 → T5 → T6) with T7 alongside T4/T6; T8 last. Commit after T3 (in-browser
gen), after T6 (API wiring), after T7 (auth).

## Testing & verification
Reuse Phase 2 domain tests (now browser-run). Manual end-to-end client-side: upload →
parse → edit grid → generate → download → email → credit consumed once, for all companies.
Confirm zero secrets in the published bundle.

## Rollback
Keep the old Server app deployable until Phase 4 parity. Revert per commit.

## Definition of done
- [ ] `ATAFurniture.Client` is UI-only (no EF/DB/secret refs).
- [ ] Parsing + generation run in-browser; downloads need no server hop.
- [ ] Auth is MSAL + bearer; API calls authenticated.
- [ ] Fire-and-forget, null-deref, whole-file-discard bugs fixed.

## Phase-specific risks
| Risk | Mitigation |
|---|---|
| Auth rewrite subtly wrong | De-risk via Spike C; test 401/redirect paths early. |
| WASM single-thread blocks on big files | Acceptable for expected sizes; revisit with a Web Worker if needed. |
| Payload too large | MudBlazor (light) + trimming; AOT if required. |

## If Spike A failed (server-side generation fallback)
Add `POST /api/generate` (accepts edited details + company → file bytes). The client
uploads/edits, calls it, and downloads the result; `Kroiko.Domain` stays on the Api.
Record via a superseding ADR to [ADR-0004](../adr/0004-client-side-file-generation.md).
